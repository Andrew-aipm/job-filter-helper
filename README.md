# 职位筛选助手 · BOSS 直聘列表 AI 初筛

一个 Chrome Manifest V3 扩展：在**你自己筛选好条件**的 BOSS 直聘职位列表页采集岗位卡片，交给 DeepSeek 按你的简历和求职要求做语义匹配，只把初筛通过的岗位导出为 Excel。

> 本工具只做**列表初筛**，不会自动投递、不会自动给招聘者发消息，也不读取 Cookie。完整岗位要求仍需你点开详情页核实。

## 功能

- **列表采集**：一键采集当前列表已加载的职位卡片（每轮最多 200 条），自动滚动、点击分页/加载更多，按详情链接去重。
- **7 天去重**：同一岗位（按规范化后的 `/job_detail/<id>.html` 链接）7 天内只入库一次，不占本轮新增额度；清空职位列表仍保留去重记录。
- **简历匹配**：简历 + 求职要求 + 职位卡片一起交给 DeepSeek 判断，输出方向相关性、硬门槛核对、0–100 评分和理由。
- **只导出通过的岗位**：匹配分达到阈值（默认 70）且没有硬门槛冲突、方向明确相关，才会出现在列表和 Excel 中；证据不足统一标为「待核实」。
- **本地优先**：简历、求职要求、采集结果、API Key 全部保存在 `chrome.storage.local`，不经过任何自建服务器。
- **Excel 导出**：内置极简 OOXML 写入器，无第三方依赖，导出岗位名称、公司、薪资、地点、匹配分、理由和列表原文。
- **打招呼模板**：4 条可编辑、可复制的通用模板，填写完自己复制，不会自动发送。
- **最小权限**：`activeTab` / `scripting` / `storage` / `alarms`；DeepSeek API 域名为可选权限，首次分析时才会申请。

## 安装（开发者模式）

1. 克隆本仓库，或下载 Releases 里的 `zip` 并解压，保证 `manifest.json` 位于所选目录的根下。
2. 打开 `chrome://extensions`，右上角开启「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择 `extension/` 目录（源码方式）或解压后的目录（Release 方式）。
4. 建议将扩展固定到工具栏。Chrome 最低版本 120。

## 使用

1. 登录 BOSS 直聘，在职位列表页手动设置城市、薪资、经验等筛选条件。
2. 点击扩展图标 →「开始采集（最多 200 条）」。可以关闭弹窗，但**保持 BOSS 标签页打开**，采集期间不要改动网站筛选条件。
3. 采集完成后点击「打开分析工作台」，粘贴或导入简历、填写求职要求、设置最低匹配分，保存资料。
4. 填入 DeepSeek API Key（在 <https://platform.deepseek.com/> 申请），点击「保存」后 Key 会锁定并保存在本机。
5. 点击「AI 分析」，逐个分析职位卡片；分析期间保持工作台标签页打开，可随时「停止分析」。
6. 分析完成后，下方列表只显示匹配通过的岗位；点击「导出合适岗位 Excel」才会下载文件。

清空职位列表不会清空 7 天去重记录；如需重新采集同一批岗位，请等待 7 天或清除扩展存储。

## 匹配逻辑

对每个岗位，扩展把 `简历 + 求职要求 + 卡片内容` 发给 `deepseek-flash`，要求模型返回结构化 JSON：

- `direction`：岗位方向与简历经历的相关性（`match` / `mismatch` / `unknown`），由模型判断，本地代码只校验枚举值。
- `hard_checks`：学历、经验等硬门槛逐条核对（`pass` / `fail` / `unknown`）。
- `score`：0–100 分；`sufficient`：信息是否足以完成列表初筛；`reason`：依据与缺口。

本地判定规则（`matching.js`）：

| 条件 | 结果 |
| --- | --- |
| 方向为 `mismatch`，或任一硬门槛 `fail` | 不匹配 |
| 方向 `unknown`、硬门槛 `unknown`、缺字段或分数非法 | 待核实 |
| 方向 `match` 且分数 ≥ 阈值 | 推荐（出现在列表和导出中） |

为避免重复调用 API，每条分析结果都带有指纹（简历、要求、阈值、模型、规则版本）；任一项变化，旧结果自动失效，需要重新分析。导出的 Excel 只包含当前仍有效的「推荐」岗位。

## 隐私与数据

- **保存在本机**：`chrome.storage.local` 中的 `profile`（简历与求职要求）、`jobs`、`captureHistory`、`deepseekKey`。
- **仅发送给 DeepSeek**：点击「AI 分析」时，简历、求职要求、职位卡片正文会发送到 `https://api.deepseek.com`。不分析就不会发送。
- **API Key 明文保存**：`chrome.storage.local` 不是加密保险箱，能访问该 Chrome 用户目录的程序都可能读取它。共用电脑请在用完后点击「清除已保存Key」。
- **不采集**：不读取 Cookie、不打开详情页、不发送站内消息、不自动投递，也不把数据发往其他服务器。
- **数据生命周期**：清空职位列表会删除 `jobs` 但保留 7 天去重记录；卸载扩展或清除扩展数据会一并丢失。

## 已知限制

- 页面解析依赖 BOSS 直聘当前的 DOM 结构（`.job-card-wrapper`、`.job-name`、`.salary` 等），网站改版后可能失效，需要更新 `capture.js`。
- 采集是模拟滚动/点击，间隔约 15 秒；浏览器休眠、标签页后台节流都会让进度变慢或暂停。
- 网站可能出现登录失效、安全验证或访问频率限制，扩展检测到后会停止并保留已采集结果，此时请手动处理。
- AI 判断基于列表卡片，不是完整 JD，结论仅供初筛；模型可能出错，投递前请自行核对。
- 每轮最多 200 条新增岗位；翻页/滚动策略未对所有地区、账号的页面样式做穷举验证。

## 项目结构

```
extension/
├── manifest.json      # MV3 配置、权限
├── popup.html/js      # 工具栏弹窗：启动/停止采集、打开工作台
├── background.js      # 采集循环：约 15 秒一轮，调用 capture.js，驱动滚动/分页
├── capture.js         # 内容脚本：解析列表卡片、滚动/翻页/加载更多
├── dashboard.html/js  # 工作台：资料、结果表格、导出
├── ai.js              # DeepSeek 调用、Key 管理、分析主流程
├── matching.js        # 判定规则、结果指纹（缓存失效）
├── history.js         # 7 天去重与 200 条上限
├── greetings.js       # 打招呼模板（不自动发送）
├── xlsx.js            # 极简 OOXML / ZIP 写入器
└── style.css          # 页面样式
```

## 开发

无需构建步骤，修改后到 `chrome://extensions` 点击「重新加载」即可。

- 语法检查：`node --check extension/*.js`
- 调试后台采集：`chrome://extensions` → 本扩展 →「服务工作线程」→ Console
- 调试工作台：打开工作台页面 → 右键「检查」

`history.js`、`matching.js`、`xlsx.js` 是不依赖 DOM 的纯函数，便于单独做单元测试。
